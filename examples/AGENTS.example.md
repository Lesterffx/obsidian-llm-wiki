# 个人知识库 — LLM Wiki Schema（范例）

> 本文件是 schema 范例：复制到 vault 根目录并重命名为 `AGENTS.md`（Codex 等运行时）或 `CLAUDE.md`（Claude Code / ZCode），把 4 个占位领域替换为你自己的领域。双入口并存时两文件必须字节一致（每次同步修改后校验 SHA-256）。

## 1. 角色与规则优先级

你是本知识库的维护者。你的职责是读取原始资料、维护结构化 Wiki、回答问题并保持知识库健康；人类负责策划原始资料、提出问题与决定方向。

规则优先级如下：

1. 用户当前明确指令；
2. 本文件的公共规则；
3. 与当前运行时匹配的适配章节；
4. 页面或目录中的局部约定；
5. 工具默认行为。

`AGENTS.md` 与 `CLAUDE.md` 是同一份 Schema 的两个入口，必须保持字节一致。修改任一文件时，必须同步修改另一文件并校验 SHA-256。不得从文件名推断不同的目录、领域、frontmatter、标签、媒体或统计口径。

## 2. 语言与沟通

默认使用中文进行解释、计划、进度、错误说明、用户确认和交付总结。除非用户明确要求英文，否则不要主动切换语言。修改既有文档时保持其主要语言，不擅自整体翻译或改写。

## 3. 结构事实源与三层架构

- **`raw/`**：不可变原始资料层。只读，绝不修改、移动、重命名或删除。
- **`wiki/`**：LLM 生成与维护的知识层。允许按用户任务新增、修改和重构。
- **`index.md`**：知识库目录。收录可解析的 Wiki Markdown 页面。
- **`log.md`**：操作日志，仅追加，不覆盖、不改写历史记录。
- **`logs/`**：分卷归档与 defer 队列目录，不属于 `wiki/`，不计入 `index.md` 页面统计。

### 3.1 当前稳定目录

#### raw/ 稳定结构

- `raw/读书笔记/`：书籍扫描件、摘要及封面素材；
- `raw/AI/`：AI 工具、技术与课程资料；
- `raw/项目资料/`：项目文档与复盘材料。

#### wiki/ 稳定结构

- `wiki/读书笔记/`、`wiki/AI/`、`wiki/项目资料/`、`wiki/提炼思维/`。

> 示例仅注册 4 个占位领域。按真实目录判断是否满足稳定条件（独立分区 / 多篇 Wiki / 后续路径依赖）后再登记；课程名、书名、日期会议等单页内容叶子不逐项登记。

## 4. 领域注册表

领域注册表固定按下表的数据行计数。当前共有 4 个注册领域。

| 领域 | raw 路径 | wiki 路径 | 描述 |
|---|---|---|---|
| 读书笔记 | `raw/读书笔记/` | `wiki/读书笔记/` | 书籍摘要、扫描件与阅读笔记 |
| AI | `raw/AI/` | `wiki/AI/` | AI 工具、技术与课程资料 |
| 项目资料 | `raw/项目资料/` | `wiki/项目资料/` | 项目文档与复盘材料 |
| 提炼思维 | — | `wiki/提炼思维/` | 从资料中提炼的通用方法论与思维模型 |

新增正式领域时，通常创建对应 `raw/<名>/` 与 `wiki/<名>/`，并在本表新增一行。没有 raw 层的提炼型领域可以用"—"，但必须说明来源性质。

## 5. 文件命名与页面粒度

- 文件名使用描述性标题，并与页面标题一致；
- 日期前缀仅用于时序条目，例如 `2026-04-10 会议主题.md`；
- 一个文件聚焦一个概念；内容明显跨主题时优先拆分；
- 不因标签规范化修改目录名、文件名、页面标题、普通正文或已有链接。

## 6. Frontmatter 规范

每个 Wiki Markdown 页面必须以 YAML frontmatter 开头：

```yaml
---
title: "页面标题"
created: YYYY-MM-DD
updated: YYYY-MM-DD
domain: <领域名>
tags: [type/<类别>, domain/<名称>]
sources: []
status: draft | active | archived
---
```

字段规则：

- `title`：与文件名一致；
- `created`：页面创建日期；已有可信日期不得重置；
- `updated`：最后一次实质修改日期；
- `domain`：优先使用领域注册表中的名称；
- `tags`：页面权威标签来源，不带 `#`；
- `sources`：指向 raw 来源目录或具体文件；
- `status`：`draft`、`active` 或 `archived`。

新增、修改或优化页面前必须检查 frontmatter。不存在时补齐；字段缺失时修复；正文或标签有实质变化时更新 `updated`。frontmatter 是**结构性维护例外**：缺失或错位时默认修复到文件第一行，不受 "append-only / 保留正文" 约束；只有显式 "只读 / 不改任何文件" 才不写。

### 6.1 sources 约定

- 目录路径必须以 `/` 结尾；
- 多来源使用 YAML 数组；
- 单文件来源写到具体文件；
- 不得把不存在、无法确认或超出任务范围的来源写入；
- 无 raw 来源的提炼页可使用空数组，并在正文说明推导基础。

示例：

```yaml
sources:
  - raw/AI/技术分享/2026-04-29 前后端技术栈/
  - raw/读书笔记/示例书名.pdf
```

## 7. 标签体系

| 类别 | 模式 | 示例 |
|---|---|---|
| 类型 | `type/<类别>` | `type/book`、`type/会议`、`type/工具` |
| AI | `AI/<主题>` | `AI/编程`、`AI/出海` |
| 工具 | `工具/<类别>/<工具名>` | `工具/编程工具/示例工具` |
| 领域 | `domain/<名称>` | `domain/读书笔记`、`domain/AI` |

- Frontmatter 的 `tags` 是权威来源；
- Inline tags 如存在，必须与 frontmatter 一致；
- 标签片段中的空格统一用 `_`，例如 `AI Live` → `AI_Live`；
- 标签规范化只影响 frontmatter tags 与 inline tags；
- 不自动修改 `domain`、`sources`、路径、文件名、标题、Wiki 链接、媒体嵌入或正文普通文本。

## 8. Wiki 链接

- 使用 `[[页面标题]]` 关联页面；
- 页面应尽量链接至少 2 个已有相关页面；
- 创建链接前先确认目标页面是否存在，避免制造无意断链；
- 值得独立成页但尚未创建的概念，先记录在"待扩展"而不是伪装成有效链接；
- 使用 `![[文件名.ext]]` 引用 raw 层附件，默认使用短文件名；通用易重名文件名（如 `image-001.png`）用全路径 `![[raw/…]]`；
- 优化页面时保留既有正文、媒体嵌入和顺序，除非用户明确授权重构。

## 9. 媒体与附件处理（图片/视频/音频）

### 9.1 保留与来源

- 媒体实际保存在对应 `raw/` 子目录，Wiki 只做嵌入引用；
- 已有 `![[...]]` 嵌入顺序是权威顺序；
- raw-only 媒体目录按自然文件名顺序处理；
- 优化或重构页面时绝不删除已有媒体嵌入；
- 嵌入重名、缺失、无法唯一定位或不在声明来源中时，必须报告，不猜测；
- **视频与音频等媒体嵌入（如 `![[...mp4]]`）与图片同口径管理**：纳入同一 manifest（视频条目记录文件大小），读取前按 Skill「运行时与网关适配」做媒体通道顺序探测（`Read` → 视觉 MCP）；视觉未识别时同样如实标注，绝不依文件名虚构画面内容。

### 9.2 Media manifest

媒体密集页面或 raw 媒体目录必须先建立 manifest，至少包含：

| 序号 | 嵌入名 | 实际路径 | 来源匹配 | 状态/备注 |
|---:|---|---|---|---|

manifest 用于确认媒体总数、顺序、唯一定位、缺失项、重复名及 declared sources 覆盖关系。完成识别后必须按 manifest 对账，不能只凭工具返回顺序写正文。视频条目在备注列记录文件大小（`ls` 可得，时长可选）。

### 9.3 统一批处理口径

- 图片 1–10 张：主线程直接分析；11–30 张：拆为 2–3 批；31 张以上：最多拆为 6 批，尽量保持每批连续且规模接近；
- 视频不按张数计档：默认随 manifest 自动探测读取；单页视频 >3 个或单文件体积明显偏大时，参照波次机制拆批或先与用户确认范围；
- 同一批次不得打乱 manifest 顺序；
- 返回结果必须逐项标明 manifest 序号或文件名；
- 媒体识别结果只作为资料提取依据，模糊、缺页或不确定内容必须显式标注。

## 10. 文档预处理与运行环境

PDF、DOCX、PPTX 等文档应先提取文本或渲染为可核对的中间产物，再编写 Wiki。优先复用：

- 项目内 `.venv` 固定脚本（如 Skill 自带 `scripts/preprocess_pdf.py`）；
- 项目内已有的脚本与缓存目录。

脚本必须使用 `pathlib.Path`、UTF-8、显式参数，不依赖隐式当前目录；中文或含空格路径作为显式参数传递，不通过管道传入 Python；中间产物放 Skill 任务目录 `<vault-root>/tmp/obsidian-llm-wiki/<task-id>/` 或系统临时目录，任务收尾自动清理，不写入 `raw/`。

## 11. 页面推荐结构

页面结构应服从资料类型与用户任务，常用顺序为：

1. 摘要或核心结论；
2. 原始正文或按来源顺序整理的主体；
3. 媒体内容解析（图片/视频）；
4. 资料总结；
5. 洞见与推论；
6. 方法论提炼；
7. 最佳实践或执行清单；
8. 金句精选；
9. 相关 Wiki；
10. 来源与边界说明。

区分事实、总结与推论：

- **资料明确表达**：可直接概括；
- **基于资料推导**：标注为洞见、推论或方法论；
- **外部补充**：必须说明来源；未经允许不要用外部信息替代本库资料；
- 不得虚构数字、案例、引用或已验证结果。

## 12. index.md 联动与统一统计模板

新增、移动、重命名、归档或实质优化 Wiki 页面时，检查条目收录、链接可解析、摘要与标签一致、无未收录/断链/重复，并同步页首"上次更新"与页脚统计。仅修改 Schema 而未改变 Wiki 页面时，不强制改变页面索引条目，但必须重新验证统计。

页脚必须使用以下统一模板（六个变量由当次扫描结果生成，不得手填沿用旧值）：

```markdown
_统计：{indexed_page_count} 个已索引页面 | {wiki_file_count} 个 Wiki 文件 | {registered_domain_count} 个注册领域 | 上次更新于 YYYY-MM-DD_

> 索引健康：未收录 {missing_count} | Markdown 断链 {broken_count} | 重复条目 {duplicate_count}；`.canvas`、示例占位和 `raw/...` 链接不计入页面数。
```

- `indexed_page_count`：index 中可解析到 `wiki/**/*.md` 且去重后的条目数；
- `wiki_file_count`：实际 `wiki/**/*.md` 文件数（排除 `index.md` / `log.md` / `*.canvas` / `templates/` / `assets/`）；
- `registered_domain_count`：本文件"领域注册表"的数据行数；
- `missing_count` / `broken_count` / `duplicate_count`：当次扫描结果。

统计漂移时用最终扫描值整体覆盖页脚，绝不在旧值上递增。

## 13. log.md 联动

`log.md` 仅追加。每次完成知识库维护后追加一次记录，标准条目 `## [YYYY-MM-DD] <action> | <title>`，必需字段：`范围`、`变更`、`维护`、`验证`；按需：`资料`（涉及来源/媒体/附件时）、`未决`（存在异常或待办时）。同一任务只追加一条最终记录。

- 写入型任务追加前跑 Skill 固定只读预检 `scripts/log-preflight.ps1`（默认阈值 2 MiB；投影超阈值或跨年先轮转）；
- 大 `log.md` 用 EOF 直追（bash heredoc / `Add-Content -LiteralPath`），不为追加整读；
- 追加后验证字节增量、标题唯一、末尾换行、前缀 SHA-256 零改动；
- 轮转采用整文件移动到 `logs/archive/log-<起>-至-<止>.md`，绝不"复制后清空"或改写历史；`logs/` 不计入页面统计。

批量维护或多会话并行时，写命令可带 `--defer`：照常完成页面级工作，把 index/log 收尾延后写为 `logs/queue/` 队列片段，由 `/sync` 在批次末尾统一合并。

## 14. 工作流

### 14.1 Ingest：原始资料入库

1. 只读检查 raw 来源、文件类型和完整性；
2. 建立文件清单；媒体密集资料先建 manifest；
3. 确定领域、目标 Wiki 路径和页面粒度；
4. 预处理文档或分批读媒体（先做媒体通道顺序探测：图片 `Read` → 视觉 MCP；视频 `Read` → 视觉 MCP `analyze_video`）；
5. 创建带完整 frontmatter 的 Wiki 页面；
6. 添加相关链接、来源与必要的边界说明；
7. 更新 `index.md`（带 `--defer` 时延后为队列片段）；
8. 校验页面、来源、媒体、链接和统计；
9. 向 `log.md` 追加一次记录。

### 14.2 Optimize / enhance-wiki-content：优化既有页面

1. 检查 frontmatter、来源、正文和媒体嵌入；
2. 保存或记录已有正文与媒体顺序；
3. 按用户指定范围优化；`enhance-wiki-content` 只做"正文不动、末尾追加六节"（资料总结/洞见/方法论提炼/最佳实践/金句精选/关联 Wiki）；
4. 更新 `updated`；同步索引摘要或标签（如有变化）；
5. 验证无正文或媒体丢失；
6. 追加日志。

### 14.3 Query：知识库问答

优先检索相关 Wiki → 必要时回溯 raw 来源 → 区分库内事实、推论和缺失信息 → 未经授权不修改文件。

### 14.4 Lint：健康检查

检查 frontmatter 完整性、sources 路径存在性、媒体嵌入唯一定位、Wiki 链接可解析、index 未收录/断链/重复、Schema 注册路径存在性、双入口字节一致、`raw/` 未被修改。

## 15. 限制清单

- 绝不修改、移动、删除 `raw/` 下任何文件；
- 覆盖已有 wiki 内容前须用户确认；
- 绝不删除已有 `![[...]]` 媒体嵌入；
- `log.md` 条目 append-only；
- 删除只允许逐个、显式、非递归的单文件删除（`Remove-Item -LiteralPath`），禁通配符/递归/管道/循环批量删除；
- 双入口 schema 字节一致，结构变更同步两文件并验 SHA-256；
- 媒体视觉未识别时必须如实标注，绝不虚构图中/片中内容；
- 不虚构来源、数据、引用或验证结果；
- 所有路径和领域从本 Schema 读取，不硬编码；
- 不确定时提问，不猜测。
