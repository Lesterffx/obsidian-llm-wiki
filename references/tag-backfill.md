# 稀疏标签自动补齐：规则详解与验证说明

`enhance-wiki-content` 在 frontmatter 校验之外内置的一条窄例外：当页面标签**稀疏**时自动补齐主题标签。本文是规则的权威细则与验收方法；主流程见 SKILL.md「Frontmatter 与 Tag 规范化」与 enhance-wiki-content 命令定义。规则为纯文档约定，不依赖任何运行时代码。

## 1. 规则详解

### 1.1 触发条件（判定口径）

对 frontmatter `tags` 计算**有效标签集**：剔除空字符串后去重，剩余即有效标签。

| `tags` 现状 | 判定 | 动作 |
|---|---|---|
| 字段缺失 | 稀疏 | 补齐 |
| `[]` / 空值 | 稀疏（有效 0 个） | 补齐 |
| 去重后仅 1 个有效标签（如仅 `[clippings]`） | 稀疏 | 补齐 |
| 含重复但去重后 ≥2 个（如 `[AI/RAG, AI/RAG]`） | 不稀疏 | 不变（重复只报告） |
| 去重后 ≥2 个有效标签 | 不稀疏 | **零改动**（`updated` 也不动） |

### 1.2 补齐方式

- **仅追加**：保留既有标签及顺序（含 `clippings` 等工具注入标签），只追加 `tags` 中尚不存在的新标签；不删除、不重排既有标签；既有重复标签不删除，但在报告中注明。
- **证据要求**：新标签按目标 Wiki 的 Schema 与本页内容确定——类型（`type/…`）、领域（`domain/…`）及有页面内容证据的主题标签；不硬编码任何特定知识库的路径或私有内容；内容不足以确定主题时报告限制，**不为凑数虚构标签**。
- **安全边界**：YAML 无法安全解析（引号不闭合、块破损等）时**停止写入并报告**，零改动；显式只读指令（"只读 / 不改任何文件"）优先于本规则，零写入。
- **日期窄例外**：实际发生标签追加时，`updated` 更新为当天；无标签变化时沿用原日期保护规则（不刷新）。
- **inline 同步**：页面存在**明确独立的 inline 标签区**（如专门的标签行/标签节）时，只追加本次新增标签；正文、代码块与引用中的 `#tag` 一律不改；无法安全同步时报告，不强改。

### 1.3 索引与 defer/sync 联动

- **已收录页面**：只同步 `index.md` 对应条目的标签列（链接、摘要、分区位置不动）；随后按六变量精校并三处页脚同步（`indexed_page_count` 不变，操作摘要 `同步索引：更新条目标签 <页面名>`）。
- **未收录页面**：按补录流程写入条目，条目行直接携带补齐后的完整标签。
- **defer**：页面级补齐照常完成；队列片段 index 条目行的标签列写补齐后标签，加注可选元信息 `tag-sync: <说明>`，log 条目「变更」注明补齐明细。`flush_queue.py` 对白名单外键静默忽略，队列格式与脚本零改动。
- **sync**：agent 在 index 合并步读取片段，页面已有条目时不再跳过，而是**以片段标签列更新既有条目**（保留链接、摘要与分区位置），报告中列出。

## 2. 页面级验证矩阵（虚构页面 9 场景）

在临时目录构造虚构 mini-vault 逐页验证（不触碰真实 vault）。每场景记录补齐前/后的 `tags` 与 `updated`，并用逐字节 diff 断言：**除 `tags` 行与（发生补齐时的）`updated` 行外，全文零变化（含换行）**。

| # | 场景 | 构造 | 期望结果 |
|---|---|---|---|
| 1 | 缺 tags 字段 | 七字段缺 `tags` | 按缺字段流程补字段后仍属稀疏 → 追加主题标签；`updated`=当天 |
| 2 | 空数组 | `tags: []` | 追加标签；`updated`=当天 |
| 3 | 仅剪藏标签 | `tags: [clippings]` | `clippings` 保留在首位，仅追加新标签；`updated`=当天 |
| 4 | 仅 1 个主题标签 | `tags: [AI/示例]` | 保留原标签，补 `type/`、`domain/` 等；`updated`=当天 |
| 5 | 重复标签 | `tags: [AI/示例, AI/示例]` | 去重后 1 个 → 触发补齐；既有重复保留并报告；新增标签不与现有重复 |
| 6 | 已 ≥2 标签 | `tags: [type/笔记, domain/示例]` | 零改动（含 `updated`） |
| 7 | 不安全 YAML | `tags: [type/笔记, 'AI/示例`（引号不闭合） | 停止写入并报告，页面零改动 |
| 8 | 重复执行 | 场景 3 补齐后原参数重跑 | 幂等：无重复追加、`updated` 不再变化、二次 diff 为空 |
| 9 | 显式只读 | 场景 3 页面 + 只读指令 | 零写入，仅报告 |

## 3. 索引与队列冒烟验证

fixture vault 最小结构：`wiki/`（若干虚构页）、`index.md`（顶部维护块 + 分区表 `| 页面 | 摘要 | 标签 |` + 底部统计行与索引健康行）、`log.md`、`logs/queue/`。

1. **已收录 + 标签列同步**：稀疏页已有索引条目 → 按 §1.3 更新标签列 → 运行 `references/index_stat.py <vault> --json`，断言 `footer_match=true` 且 `indexed_page_count` 不变。
2. **未收录 + 补录**：稀疏页无条目 → 补录条目携带补齐后标签 → `index_stat.py` 断言 `indexed_page_count` +1 且 `footer_match=true`。
3. **defer + sync 一致性**：对稀疏页写含 `tag-sync` 元信息的队列片段（index 条目行为补齐后标签）→ `scripts/flush_queue.py --vault-root <vault> --dry-run`（退出码 0，片段计入 merged）→ 实跑合并（log 条目追加、片段单文件清理）→ 按 §1.3 更新既有条目标签列 → `index_stat.py` 复验 `footer_match=true`，且与场景 1/2 的条目标签口径一致。
4. **脚本零回归**：`flush_queue.py --help`、空队列运行、非法片段（缺围栏）报告 `invalid` 等既有行为不变（本规则未改动任何脚本代码）。

## 4. 元数据与换行保持检查

- 对每场景保留补齐前副本，`diff` 逐行对比：仅允许 `tags` 行与 `updated` 行变化；无标签变化的场景必须零 diff。
- 页面若以无换行符结尾，补齐后仍须以相同方式结尾（不补尾巴换行）。
- 重复执行（场景 8）后二次 diff 必须为空，证明幂等。
