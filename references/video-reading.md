# 视频阅读（Video Reading）

`ingest`、`optimize`、双参数 `enhance-wiki-content` 范围内的视频默认读取。本参考为这三种流程补充视觉视频证据，不放宽任何命令的来源、元数据、正文、index、defer 权限。选项定义、manifest 纳入口径与通道探测顺序以 SKILL.md 对应章节为准（§--no-video 参数、§媒体密集资料分析、§运行时与网关适配）；本文件细化抽样预算、字幕证据、清理与收尾。

## 选项与路由

- 视频阅读对这三种流程默认开启。`--no-video` 与 `--defer` 均放在命令名之后、位置路径参数之前，二者任意顺序；在任何写入（含临时产物）之前拒绝未知、重复、错位的选项与非法路径个数，不把选项当路径。
- `--no-video` 跳过：视频能力探测、ffprobe、视频内容哈希、抽帧、视频视觉工具、附属字幕发现与读取。media manifest 保留既有视频引用的清单位置并标注"视觉未识别（--no-video 跳过）"，页面正文照常可用，继续处理图片与文字。不得为了记录一次跳过而空跑 helper。
- 单参数 `enhance-wiki-content` 无论有无 flag 始终纯正文：不做 raw 媒体与字幕发现、视频探测、临时产物；保留其窄口径规则（缺字段补齐、稀疏标签、既有正文限制）。
- `--defer` 只改变共享文件收尾方式：读取与页面级验证照常完成，把通道/覆盖结论写入私有队列片段，不改 index/schema/log 共享文件。队列 v1 与 helper 接口不变。
- `query-image`、`update-raw-reference`、`sync` 等其他命令不获得视频阅读行为或 `--no-video` 选项。

```text
$obsidian-llm-wiki ingest "raw/<领域>/<资料>/"
$obsidian-llm-wiki optimize --no-video "wiki/<领域>/<页面>.md"
$obsidian-llm-wiki enhance-wiki-content --defer --no-video "wiki/<领域>/<页面>.md" "raw/<领域>/<资料>/"
```

## 有序媒体 manifest

- 扩展现有内存 media manifest，不另建排序体系、不改写引用语法。大小写不敏感识别视频扩展名：`mp4/mov/webm/m4v/mkv/avi/ogv`。音频引用仅入清单：不播放、不转写音频。
- 纳入两类来源：真实 Obsidian 媒体嵌入（`![[...mp4]]`）与指向 raw 的本地 Markdown 视频附件链接（如 `[clip](<../../raw/.../clip.mp4>)`）。排除 frontmatter、代码块、转义语法与注释。先按 Markdown 语法解析、再一次性解码本地目标路径，绝不解码 Obsidian 文件名；不跟随远程 URL、HTML、引用定义或不支持的语法。相对 Markdown 链接从页面目录解析，显式 `raw/...` 库内路径从 vault 根解析。
- 每个来源位置记录：稳定序号、原始表达式与语法形态、媒体类型、实际路径、来源匹配、大小、探测时长（如有）、通道、覆盖与读取状态。重复引用保留为独立位置，确认文件唯一身份后才可复用分析。帧序号归属其父视频序号，绝不替代来源位置。引用数、唯一视频数、抽帧数三个计数分开维护。
- 沿用所在命令的既有真实路径边界（含 junction/symlink）。双参数增强的读取范围限于所给 raw 目录：绝不把显式引用重定向到其他来源，不读范围外文件，文件级来源不授权兄弟文件。保留缺失/歧义/越界引用并如实报告，不猜测。raw-only 目录用自然文件名顺序。范围内未被引用的视频只做对账报告，不插入新嵌入；非嵌入附件仍是来源证据，不构成改写其语法的理由。

## 能力探测与本地抽样

1. 先建清单，再做任何能力断言。只认当前运行时实际暴露且当次验证过的能力；其他运行时的工具名、凭据与实测上限（含 SKILL.md 通道矩阵的历史记录）只作探测起点提示，不构成本次能力证明。
2. 运行时实际暴露已授权的原生视频工具时（如 `Read` 视频通道、视觉 MCP `analyze_video`），按 SKILL.md「视频顺序探测」先用一个小的代表性范围内视频探测：成功标准是返回带可溯时间戳的画面或真实视觉解读；文件名、元数据、URL 或上传回执不算成功，探测证据可复用。单个视频超出该工具限制时仅该条目转本地路径，不阻塞其他视频。
3. 无可用通道、或单视频超限、或需要更长覆盖时，用既有本地 ffprobe/ffmpeg 配合下方固定 helper。先确认看图能力可用——先读一张生成的帧，确认能返回视觉内容再批量；看图失败则不为其余视频生成/读取、不派发注定失败的批次，保留清单并标注视觉覆盖不可用。
4. 需要视觉 MCP 时只用已配置且已授权的：不安装服务、不加凭据、不上传新目的地、不试其他运行时的网关。本地抽帧 ≠ 本地推理——帧由当前模型服务读取，沿用其既有数据传输权限与隐私边界。

helper 用项目 Python（按 SKILL.md「Windows 与 Python」优先序）运行，全部路径为显式参数，无 shell 替换、无源文本命令：

```bash
"$VAULT/.venv/Scripts/python.exe" -X utf8 -B "<skill_base>/scripts/preprocess_video.py" \
  --input "<raw 视频绝对路径>" \
  --vault-root "<vault 绝对路径>" \
  --source-scope "<已确认的 raw 目录或文件>" \
  --task-id "<唯一安全任务 id>"
```

- helper 只用 Python 标准库与既有 `ffprobe`/`ffmpeg` 可执行文件：不安装任何东西、不改 PATH、媒体协议限本地文件。
- **先校验工作流参数与安全 frontmatter，再做任何预处理**：非法增强不得产生哪怕临时文件。
- 每个唯一视频用全新 task id；helper 拒绝已存在的任务目录，并校验源真实位于 vault 的 raw 与所给 source-scope 内。helper 不读 URL，不改 raw/wiki/index/log/schema 任何文件。
- 默认抽样目标：每 5 秒一帧加末段，每个视频最多 60 帧；长视频在整条时间线上均匀扩大间隔。缩放保宽高比、最大宽 1600 像素；读不清的小字如实披露，不推断。
- `video-manifest.json` 记录：源 SHA-256、大小/时长、请求抽样时间、解码到的源 PTS 与相对时间线时间（可得时）、逐帧解码失败、字幕候选、源哈希复核结果。未知实际时间戳记 null；绝不把帧序号或请求寻址时间当观测时间报告。
- 按 manifest 顺序读取每个成功帧，或显式标注未读位置；观察归属父视频与可用时间。视频数不等于图片数，沿用既有图片分批与委派权限规则；主 agent 默认亲自读帧，明确授权后才委派。
- 抽样必然漏掉帧间的瞬态、语音与细节：表述用「抽样画面分析」，写明间隔/帧数与局限，绝不声称完整播放、精确转写或完整覆盖。
- 工具缺失、文件损坏或流不支持只影响该视频：继续其他已验证证据，不重复硬试同一失败。**没有可用证据就不写内容。** 源哈希在处理后发生变化会使该视频证据失效，必须报告。

## 既有字幕

- 可见字幕属于视觉证据。页面正文、既有字幕文件证据分别标注，都不得表述成"从录音中听到"的内容。
- helper 只在视频同目录报告同主名的 `.srt`/`.vtt` 候选，且真实路径须在 raw 与已确认 source-scope 内：单候选即可用，多候选记 ambiguous 不自动选择，无候选记 absent。其他显式引用的 SRT/VTT 文件，须 agent 先核范围与关联后才可读取。字幕按 UTF-8 读取（允许 BOM），编码不支持就报告而非猜测。文件级视频输入不授权兄弟字幕。损坏的视频仍可有独立验证的字幕证据，但这不等于视觉成功。
- 禁止递归搜索其他目录、抽取语音、运行 ASR、或把模型的视频回复当作音频转写；`--no-video` 同样跳过本字幕文件分支。

## 保留、清理与收尾

- 视频观察可用于与图片相同的授权综合小节（资料总结/洞见/方法论提炼等）。双参数增强仍在 EOF 追加，保留旧字节与既有例外、元数据限制、媒体后缀/数量/顺序与不新增嵌入规则。稀疏新标签可用范围内的视觉/字幕证据；单参数标签仍只用本页正文。
- 全部产物在 `<vault>/tmp/obsidian-llm-wiki/<task-id>/` 下。helper 对成功与受控失败都维护 `created_files.json`，自身从不删除任何文件。收尾按 [temp-cleanup.md](temp-cleanup.md)：冻结确切清理清单，逐个已登记字面路径文件校验后删除，再按最深优先删除已登记空目录；保留受保护的 `tmp/` 与其他工作流。禁止自动递归清理或删除源，受控残留如实报告。
- 最终普通 log 条目或 defer 队列片段之前，记录：通道/探测结论、抽样/跳过/未决视频数、帧覆盖、字幕证据、源哈希结果与清理状态。无写入与只读工作流保持其原有零写入规则；不因读过一次视频就持久化能力断言或修改 vault schema。
- 公开发布只包含通用说明、helper 代码与合成测试源。绝不提交视频、字幕、抽帧、真实名称/路径、源哈希、私有 manifest、清理清单、日志或试跑目录。
